# ドキュメント目次

このディレクトリには、 `Yu-Gi-Oh! ソリティア` の**ストック情報**（永続的な知識）が整理されています。

---

## 💡 プロジェクトコンセプト

### 課題と目的

**課題**:

- 遊戯王の「ソリティア（1 人で延々とコンボを回す行為）」は、実カードの収集や練習が煩雑
- 自分は楽しいが、対戦相手はつまらない（壁とやってろ）
- 特定のデッキで勝利までのルートに挑戦したいニーズがある
- 過去に猛威を振るったワンキルデッキは、主要パーツのエラッタ・禁止により再現が難しい

**目的**:

- Web ブラウザ上で手軽に「先攻 1 ターンキル」に挑戦・練習できる環境を提供する

### コンセプト

**ソリティア感覚でプレイする、 1 人プレイ用の遊戯王 1 ターンキル・シミュレーター**

- ユーザーはデッキを選ぶだけで、即座にゲームを開始できる
- 「全盛期」のカード・ワンキルデッキを体験できる
- 対戦相手はカカシで、気兼ねも思考待ち時間もゼロ、優先権も考慮不要
- 先行 1 ターン目に絞ることで、複雑な戦闘ダメージ計算等の実装は不要
- カードプールを絞ることで、大量かつ複雑な実装は不要

---

## 🔍 スコープ方針

### やること (In Scope)

- **先行 1 ターン目のゲーム進行**: 1 キルシミュレーターに必要な範囲に絞ったゲーム進行管理システム
- **プリセットデッキ選択**: プレイヤーは、あらかじめ定義されたデッキから選択
- **プリセットカードプール**: プリセットデッキに含まれるカードプールに必要なカードの効果処理のみ実装
- **勝利判定**: ライフポイント、デッキ切れ、またはプリセットデッキで達成可能な特殊勝利

### やらないこと (Out of Scope)

- **デッキ構築機能**: カードプール爆発の防止
- **バトルフェイズ**: 先攻 1 ターン目には不要
- **相手プレイヤー**: 基本的には何もしないカカシ（必要に応じて、ランダム選択等の軽量ルールベース処理）
- **優先権システム**: 相手プレイヤーが何もしないため、不要

## 🗂️ ドキュメント構成

ドキュメントを **「何を作るか（問題領域）」** と **「どう作るか（アプローチ）」** の 2 軸で分ける。

```
# ストック情報（永続的な情報）
docs/
├── README.md         # 全体概要（本ドキュメント）
├── game-rules/       # 何を作るか: 遊戯王のルールそのもの
└── design/           # どう作るか: このアプリをどう設計・実装するか

# フロー情報（spec-kit による作業記録）
specs/
├── README.md         # spec-kit 運用ポリシー
├── 0xx-feature-name/ # 1ショットの作業単位（未コミット）
└── ...
```

### 各ディレクトリの責務

| ディレクトリ    | 役割                     | 書くこと                                                     | 書かないこと                     |
| --------------- | ------------------------ | ------------------------------------------------------------ | -------------------------------- |
| **game-rules/** | 何を作るか（問題領域）   | 遊戯王のルール。FW非依存・不変の仕様                         | 実装識別子・パス・実装状況の転記 |
| **design/**     | どう作るか（アプローチ） | レイヤー設計・パターン・データフロー・**判断の指針（なぜ）** | ルールの再説明（リンクで誘導）   |

### ドキュメント間の依存ルール

クリーンアーキテクチャの依存ルールを、ドキュメントにも適用する。  
**依存の矢印は常に `game-rules/`（内側・安定）に向かう。逆向きは禁止。**

- **`game-rules/` は、他のどのドキュメントにも依存しない。**
  - 遊戯王のルールそのものだけを記述する。普遍的で、このアプリが無くても成立する知識。
  - 実装識別子・ファイルパス・実装状況の転記はしない（実装の都合で問題領域を汚染しないため）。ただし概念の正式名称（ユビキタス言語）を定義するのは game-rules の役割。
- **`design/` は、`game-rules/` を参照してよい。**
  - ルールを再説明せず、`game-rules/` へリンクする。同じ説明を 2 箇所に書かない。

この一方向依存により、「どっちに書くか迷う」「同じ話が両方に書かれて片方だけ古くなる」漏れを防ぐ。
